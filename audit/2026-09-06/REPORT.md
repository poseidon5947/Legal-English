**Legal English 5 — UI, UX and functional audit · 6 September 2026**

The website has a coherent visual style and usable core learning screens, but it is not ready for production launch. Account and Owner Admin can crash on direct navigation; production logout, audio playback and paid subscription management are incomplete or broken. Access enforcement and failure recovery also need attention before visual polish.

This audit reviewed the local project, not a deployed domain. Tests ran against an isolated production build in `/tmp/le5-deep-audit/app`, using alpha data and disposable accounts. Your original application source and alpha data were not changed. Supabase, actual email delivery and Mercado Pago were reviewed in code; they were not tested against live services. Findings below distinguish reproduced behavior from source-confirmed production defects.

**Coverage and successful checks**

- Production build, TypeScript check and all eight existing test files passed. Their passing results did not detect the runtime hook-order crashes.
- 60 route/viewport/state checks covered public pages, login/signup, empty and populated learner experiences, dashboard, terms, categories, saved library, both quiz routes, progress, account/settings/achievements/help, billing, term detail/quiz, invalid routes and Owner Admin. Widths: 1440 and 390 pixels, with additional 768-pixel checks. These covered page templates; they were not exhaustive checks of every content permutation or device.
- No horizontal document overflow or broken loaded images was detected in that sweep. Six checks displayed the application error boundary despite HTTP 200. The sweep’s accessibility name checks found no obvious unnamed visible buttons or unlabeled visible inputs in the rendered states; that is not an accessibility conformance assessment.
- Browser login, library search, successful quiz submission and alpha audio delivery passed. Audio returned `200 audio/mpeg` with actual bytes.
- Alpha API signup, verification, profile change, password change, learner export and disposable-account deletion passed. Alpha logout cleared the session. Guest and learner requests to Owner Admin returned 403.
- Import preview accepted the supplied v1.3.81 workbook without issues: 30 terms, 117 collocations, 30 context entries, 30 quizzes, including 12 three-option and 18 four-option quizzes. Commit updated 30 existing terms without inserts, rollback succeeded, Owner export returned 200, and an invalid audio filename was rejected.
- English/Spanish selection survived reload. All 19 homepage reveal groups became visible when scrolled through. Mobile drawer opening and Escape closing worked after animations settled.
- Local homepage measurements included approximately 795 KB of resource transfers after a full mobile scroll. Localhost timing is not evidence of real-user performance; no throttled mobile or production Core Web Vitals assessment was performed.

Raw coverage and reproduction results are in [evidence](evidence/route-coverage.json).

**High-priority functional findings**

**1. Account and Owner Admin crash when session data arrives after the first render.** **High · reproduced.** Directly open or reload `/account`, `/account/settings`, or `/admin` while signed in. The page can show “This page could not be opened.” Delaying bootstrap by 400 ms reproduced React error #310 for both Account and Admin. Client navigation after the session has loaded can work, which makes this easy to miss in casual testing.

Cause: Account returns early at [components/account-workspace.tsx:139](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/account-workspace.tsx:139) before the `useState` at line 146; Admin returns at [app/admin/page.tsx:75](/home/user/Pictures/E-learning/legal-english-5-mvp-app/app/admin/page.tsx:75) before `useState` at line 85. Move every hook above conditional returns. Add browser regression checks for direct entry, reload and delayed bootstrap. Evidence: [Account error](evidence/learner-1440-_account.png), [Admin error](evidence/owner-1440-_admin.png), [console results](evidence/extra.json).

**2. Production logout does not end the Supabase session.** **High · source-confirmed; live production untested.** [app/api/auth/route.ts:28](/home/user/Pictures/E-learning/legal-english-5-mvp-app/app/api/auth/route.ts:28) returns success without calling Supabase sign-out. [lib/api.ts](/home/user/Pictures/E-learning/legal-english-5-mvp-app/lib/api.ts) clears only alpha cookies; neither the store interface nor the production store implements logout. The client clears its own state, but production authentication remains available on refresh. Add a backend logout operation that revokes/clears the Supabase session, then verify bootstrap is anonymous after reload.

**3. Production term audio requests an endpoint that always returns 404.** **High · source-confirmed.** [components/term-detail.tsx:122](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/term-detail.tsx:122) always sets the player source to `/api/media/{id}/{jurisdiction}`. That route explicitly returns 404 outside alpha mode, while the production store already supplies signed storage URLs. Use the appropriate returned audio URL and provide visible playback errors. Also refresh expiring signed URLs for long study sessions; they currently have a 30-minute lifetime with no playback refresh path. Alpha audio delivery passed; this does not validate production playback.

**4. Subscribe, upgrade and cancel are not connected to production checkout.** **High · source-confirmed.** [app/billing/page.tsx](/home/user/Pictures/E-learning/legal-english-5-mvp-app/app/billing/page.tsx) calls `applyBilling()` for subscription actions. [lib/store.supabase.ts:556](/home/user/Pictures/E-learning/legal-english-5-mvp-app/lib/store.supabase.ts:556) deliberately rejects these calls, and the page ignores the returned error. The visible controls therefore cannot complete production purchases or cancellation. Pricing selections also discard plan intent by linking to generic login. Implement provider checkout and cancellation, preserve the selected plan, and display pending, success and failure states. This is an acknowledged unfinished delivery item in the README, but the customer-facing UI currently presents it as available.

**5. Expired accounts still receive protected learning content.** **High · reproduced in alpha; matching production code gap.** After expiring a learner trial, `/api/bootstrap` returned `allowed:false` alongside all 30 published terms, definitions and quiz answer keys. The alpha audio endpoint correctly returned 403, but hiding the term page does not protect the text payload.

[lib/store.ts:303](/home/user/Pictures/E-learning/legal-english-5-mvp-app/lib/store.ts:303) filters publication, not entitlement. Production bootstrap similarly calls `listTerms()` without entitlement enforcement; the supplied term/quiz RLS policies check publication only. Production audio signing uses the service role after that query, so expired accounts can also receive signed audio URLs. Apply access checks before returning full content or issuing URLs. Return a deliberately limited library summary where browsing without active access is intended. Evidence: [expired-account results](evidence/flows.json).

**6. A signed-out request can reset the entire alpha data store.** **High for an exposed alpha deployment · reproduced.** Posting `{action:"reset-store"}` to `/api/auth` without a session returned 200 and reset the isolated copy. [app/api/auth/route.ts:47](/home/user/Pictures/E-learning/legal-english-5-mvp-app/app/api/auth/route.ts:47) performs no owner check. Restrict reset to an authenticated owner and an explicitly enabled local/demo environment. Production currently throws rather than resetting, so this finding is specifically about alpha deployments. The test never reset your original store.

**7. Network failures strand loading and submission states.** **High · reproduced.** Abort `/api/bootstrap` and visit `/dashboard`: the screen remains “Opening your studio…” with no retry action. Abort `/api/learn` during a quiz: “Check Answer” remains disabled and no error appears. [components/app-provider.tsx:125](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/app-provider.tsx:125) does not catch bootstrap failure; [components/quiz-workspace.tsx:117](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/quiz-workspace.tsx:117) clears busy state only inside a resolved promise. Term quiz/report handlers have the same pattern. Use explicit error states, `catch`/`finally`, retry actions and preserved user input. Evidence: [failure results](evidence/flows.json).

**8. An authentication failure is recorded as an incorrect quiz answer in the current session.** **Medium · reproduced.** Return `{ok:false,message:"Sign in required."}` with HTTP 401 from `/api/learn`. The quiz displays “Not quite. Sign in required.” and increments the local answered/missed counters. [components/quiz-workspace.tsx:120](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/quiz-workspace.tsx:120) converts missing `correct` to false without checking `ok`; term detail does likewise. Validate the operation succeeded before scoring it, then offer reauthentication without losing the selected answer.

**Access and data correctness**

**9. Alpha learning actions accept unavailable or nonexistent terms.** **Medium · reproduced.** After an owner unpublished `CON-010`, a learner could still submit its quiz and receive the answer explanation. Opening `NO-SUCH-TERM` returned success and created progress. [lib/store.ts:321–370](/home/user/Pictures/E-learning/legal-english-5-mvp-app/lib/store.ts:321) lacks consistent term existence/publication/archive checks; favourites also bypass entitlement/disabled checks. Validate the resource and user access on every mutation, and do not create orphan progress. Production has some protection through term RLS, but progress writes also need explicit validation and error handling.

**10. Deactivated learners can still retrieve alpha audio.** **Medium · reproduced.** Deactivate a learner, then request `/api/media/CON-001/us`: it returns 200. [app/api/media/[termId]/[jurisdiction]/route.ts](/home/user/Pictures/E-learning/legal-english-5-mvp-app/app/api/media/[termId]/[jurisdiction]/route.ts) checks subscription entitlement but not `disabledAt`. Apply the same deactivation policy to audio, content and learning mutations. Reactivation itself worked through the alpha API.

**11. “Quiz Accuracy” measures latest mastery, not answer accuracy.** **Medium · source-confirmed.** [lib/learner-stats.ts:61](/home/user/Pictures/E-learning/legal-english-5-mvp-app/lib/learner-stats.ts:61) computes mastered terms divided by terms ever quizzed. Nine wrong attempts followed by one correct answer on a single term yields 100%, even though answer accuracy was 10%. Persist correct/incorrect attempt events or label the current metric to match its meaning. The history column is already labeled “Attempts” and category bars “Category Mastery”; those labels should be preserved.

**12. Streaks and activity history lose earlier learning days.** **Medium · source-confirmed.** `streakFor()` and `weeklyActivity()` derive history from one mutable timestamp per term. Practising the same term today overwrites evidence that it was studied yesterday; cumulative attempts are moved into the latest week. This affects progress charts and the consistency achievement. Store dated learning events or daily aggregates, and calculate streaks with calendar-day comparisons across daylight-saving changes.

**13. Privacy and notification settings are browser-local switches without the promised backend behavior.** **Medium · source-confirmed.** [components/account-workspace.tsx:50–119](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/account-workspace.tsx:50) saves these settings under shared localStorage keys. Study reminders and weekly progress summaries have no delivery implementation. Privacy switches do not update a server-side preference. These values also follow the browser across accounts and do not synchronize across devices. Implement account-scoped persistence and the described behavior, or clearly mark unavailable features and remove misleading controls.

**UI, navigation and accessibility**

**14. Mobile layouts prioritize supporting material above the task.** **Medium · measured and visually reviewed.** At 390×844, the login email input starts about **1,230 px** below the top of the document: a returning learner sees a full promotional panel before any login fields. On Terms, three large category cards precede the actual terms; on Quizzes, four stacked statistics precede the active question. Put the mobile login form first, use compact category navigation, and place the question ahead of secondary statistics. Evidence: [mobile login](evidence/login-mobile-viewport.png), [mobile Terms](evidence/learner-390-_terms.png), [mobile quiz](evidence/learner-390-_quizzes.png).

**15. “Need help?” sends signed-out users back to login.** **Medium · reproduced.** From login, click “Need help?”. It links to `/account/help`, whose learner shell requires a session and redirects back to login. People with login/recovery problems cannot reach support through that link. Provide a public support/contact route and use it from authentication screens. Source: [components/auth-reference-page.tsx:274](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/auth-reference-page.tsx:274) and the learner shell’s authentication redirect.

**16. Free-trial and pricing CTAs lead to the existing-user sign-in view.** **Medium · source and browser route review.** [components/landing-header.tsx:92](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/landing-header.tsx:92) and [app/pricing/page.tsx:58](/home/user/Pictures/E-learning/legal-english-5-mvp-app/app/pricing/page.tsx:58) send new-user acquisition actions to `/login`. Users must discover the Create Account tab themselves, and plan selection is lost. Route free trials directly to signup; carry pricing intent through authentication into billing. Existing users should retain a clear sign-in path.

**17. The keyboard-shortcut modal does not move or contain keyboard focus.** **Medium · reproduced.** Open the shortcut dialog: focus remains outside it. Press Tab: a background link receives focus although the dialog advertises `aria-modal="true"`. Source: [components/learner-shell.tsx:418](/home/user/Pictures/E-learning/legal-english-5-mvp-app/components/learner-shell.tsx:418). Move focus into the dialog, contain Tab/Shift+Tab, make the background inert while open, and restore focus on close. The mobile drawer also lacks deliberate focus management and should receive the same keyboard audit. Escape closing works. No screen-reader certification or full contrast audit was performed.

**18. Production support tickets have no visible owner handling workflow.** **Medium · source-confirmed.** [lib/store.supabase.ts:399](/home/user/Pictures/E-learning/legal-english-5-mvp-app/lib/store.supabase.ts:399) inserts a `support_tickets` row, but bootstrap returns an empty inbox and the owner UI has no ticket list or status/reply workflow. The alpha inbox behavior does not carry into production. Add an owner queue and a learner receipt/status view, or connect the intended support delivery channel. No actual support messages were sent during this audit.

**19. Owner Overview gives obsolete audio instructions.** **Low · reproduced.** Overview says AudioUS is 0/30 and publishing is blocked, while Terms correctly shows 30/30 recordings and 30 terms ready to publish. [lib/admin-copy.ts:28](/home/user/Pictures/E-learning/legal-english-5-mvp-app/lib/admin-copy.ts:28) and its Spanish equivalent hard-code the older state. Derive the message from current publication blockers and actual asset counts. This discrepancy can make the owner re-upload already integrated audio unnecessarily.

**Visual assessment and suggested fix order**

The navy/gold palette, serif headings, category colors and repeated navigation give the site a consistent identity. The working desktop library is easy to scan, and responsive layouts generally remain within the viewport. The homepage is long on mobile—roughly 12,800 pixels at the tested width—and repeats feature, use-case and pricing information. Shortening it would make the main trial decision easier. The fixed cookie notice is also relatively prominent on a small screen; review its size alongside the primary CTA. These are usability improvements, not demonstrated functional failures.

First fix the hook-order crashes, production authentication/audio/billing, access enforcement and unauthenticated reset. Next fix failed-request recovery and scoring semantics. Then correct learning metrics and settings behavior. Finally prioritize mobile task placement, acquisition/help routing and keyboard focus.

After fixes, run browser regression tests that assert actual page content and error-boundary absence, not HTTP 200 alone. Production acceptance still needs real Supabase sessions, email verification/recovery, signed media expiry, checkout/webhook/cancellation, production support delivery, cross-browser checks, keyboard/screen-reader review and a throttled mobile performance pass. Account avatar upload, every admin editing permutation and long-term subscription timing were not exhaustively exercised here.
